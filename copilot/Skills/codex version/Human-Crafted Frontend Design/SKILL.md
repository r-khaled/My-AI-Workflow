# Purpose

Generate frontend UI directions and implementation guidance for modern web apps that feel premium, calm, readable, and intentionally designed.

Help produce interfaces that avoid the AI-generated look by emphasizing content, typography, hierarchy, restraint, and real product thinking.

# Workflow

1. Identify the user's primary goal and the decision the screen supports.
2. Choose the smallest useful layout before adding components.
3. Establish hierarchy with typography, spacing, and content priority.
4. Design loading, empty, error, and responsive states.
5. Reuse the project's existing design system when available.
6. Remove ornamental elements that do not improve clarity or workflow.

# Required Output

Produce:

- UI direction.
- Layout structure.
- Component recommendations.
- Typography system.
- Spacing system.
- Color rules.
- Motion rules.
- Content hierarchy.
- Empty, loading, and error state guidance.
- Anti-AI design constraints.

# Design Principles

1. Make content the hero.
2. Use typography to carry the identity.
3. Use whitespace to create rhythm and focus.
4. Keep color controlled and intentional.
5. Make motion subtle and meaningful.
6. Make layout feel human, not mechanically repetitive.
7. Support real workflows and real product states.
8. Use minimalism to improve clarity, not remove usefulness.
9. Make the interface brand-specific and domain-specific.
10. Avoid generic AI-template aesthetics.

# Default Style Rules

- Use a neutral base palette.
- Prefer black, white, and muted grays.
- Add only one controlled accent when needed.
- Use elegant, highly readable typography.
- Keep spacing disciplined and consistent.
- Favor subtle borders or soft elevation over dramatic shadows.
- Keep motion minimal and functional.
- Avoid decorative clutter and overdesigned effects.

# Anti-Patterns to Reject

Reject:

- Generic centered hero blocks.
- Repetitive card grids.
- Excessive gradients.
- Glassmorphism overload.
- Loud accent colors everywhere.
- Symmetrical but lifeless compositions.
- Placeholder-looking copy.
- Screens that look polished but lack product logic.

# Required Thinking Process

For every screen:

1. Identify the user goal.
2. Identify the decision the screen supports.
3. Choose the smallest useful layout.
4. Establish hierarchy through type and spacing.
5. Verify states and edge cases.
6. Remove anything ornamental that weakens clarity.

# Success Criteria

Ensure the result feels:

- Clean.
- Premium.
- Calm.
- Confident.
- Readable.
- Modern.
- Product-first.
- Human-crafted.

# Dashboard Behavior

When asked to design a dashboard, do not produce a generic SaaS dashboard.

Instead, design a dashboard with:

- A clear primary task.
- One dominant piece of content.
- A compact supporting summary.
- A restrained visual system.
- A real workflow.
- A distinct brand feel.

# Instructions for Agent Use

When using this skill:

- Follow these rules before generating UI.
- Never default to generic templates.
- Justify every visual choice.
- Optimize for real usage, not visual noise.
- Keep the final result simple, elegant, and specific to the product.
